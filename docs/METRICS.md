# Metric contract 1.2.0 / rules 1.2.0

All dates are ISO local calendar days in a configured IANA timezone; the synthetic clock is 2026-06-29, Europe/London. Today is provisional and excluded. The default current period is June 1–28; the previous period is May 4–31. Both contain 28 completed days. Independently seeded fixtures contain 360 days. Optional 14-, 90- and 180-day views compare equally long adjacent completed periods; all period outputs change together. The 180-day view compares December 31–June 28 with July 4–December 30. For views longer than 28 days, recovery flags and their evidence retain the latest 28 versus preceding 28 days, explicitly labeled separately from selected-period means so a long average cannot hide recent concerns. The latest seven completed days remain a distinct seven-day calculation. Boundaries are inclusive. Daily records use original writer + source key, highest revision; removals excluded. Missing is null, never zero. One selected step writer is used; mirrored copies are excluded. Original writer, device, adapter, units, observation class and revisions remain attached.

Calories/protein averages include only explicitly complete logging days with finite values. Coverage denominator is every day in the window, not days returned by sync. Target variance uses each day's effective plan and only days with complete logs and known targets. Period change compares complete-day means, with coverage shown; full-period interpretation requires 100% complete logging in both windows. Whole-week means require seven complete days. Sync freshness does not establish log completeness.

Weight: latest reading, last-seven-day arithmetic average, first-to-last observed net change across the selected window, and ordinary least-squares fitted slope (kg/week, actual calendar-day offsets) are separate. Fit requires at least four readings spanning seven days; net change labels actual endpoint dates. These are scale-weight changes, not tissue changes. No estimated energy requirement or fixed energy-per-pound calculation. Optional scale fat percentage retains provider-estimate and device labels; no tissue inference. Sparse waist (<3 observations across >=14 days) is insufficient for a trend.

Strength: compare maximum recorded load for the same exercise ID, equipment, per-hand/combined convention, repetitions and source definition in each window. No conversion to e1RM. A source/equipment substitution creates a boundary. Session attendance counts unique session IDs; prescribed movement exposure is separately checked against an explicitly synthetic program. Garmin context never adds a strength session to Hevy attendance. Aerobic minutes are separate from tonnage and frequency.

Recovery: compare observed sleep duration, nightly HRV and resting HR with coverage. Synthetic rule flags a sleep decrease >=0.75 hours or RHR increase >=5 bpm when >=7 observations exist per window and both latest sleep/RHR observations fall within the last three completed days. HRV is descriptive context, not a flag or score. This is context, not a diagnosis; gaps make recovery unknown. No readiness score.

Slowdown: current fitted weight slope exceeds prior slope by >0.1 kg/week with both fits available. Incomplete intake suppresses intake explanations; source substitution suppresses only incompatible strength claims. Supported observations and plausible explanations are distinct. Rule outputs select bounded review, evidence collection, deferral or continue unchanged, never numerical prescriptions. Intended weight-change range is unconfigured unless explicitly entered.

Numbers are calculated at full precision in canonical SI units. US display uses pounds to 1 decimal, pounds/week to 2, inches to 1, miles to 2, nutrition/steps as whole units and percentages to 1. Charts and prose consume the same results. Decisions clone plan versions, full selected source revisions, metrics, rule version, choice, effective/review dates and reason. Subsequent corrections cannot rewrite the snapshot. Reassessment partitions execution by chosen effective date and reports observed response without causal claims. All scenario evidence is independently generated; tests establish software behavior only.


## Dashboard output contract

`dashboard(data, analysis, decisions)` is a projection of the shared analysis. The UI never estimates new physiological measures. Every row retains the selected inclusive current/prior windows; daily input is normalized before this core (one eligible daily aggregate per kind/writer/date, with corrections represented as revisions rather than extra daily samples).

| Identifier / field | Unit and inclusion | Comparison / denominator |
| --- | --- | --- |
| `weight.latest` / `weight.latest` | kg; latest finite current-window reading; observation date separate | No period delta implied; regression test prevents date metadata overwriting the number |
| `weight.trend` / `weight.slope` | kg/week; OLS and sparse-fit rule above | Selected current vs equal-length prior period; count / calendar days |
| `weight.mean7`, `weight.net` | kg; seven-day arithmetic mean and first-to-last selected-period reading, respectively | Seven-day count and actual endpoint dates are explicit |
| `execution.calories` | kcal/day; explicitly complete finite daily logs | Actual mean, dated-target variance over eligible dates, separate prior complete-day mean delta; current/prior coverage and eligible target-day count |
| `execution.protein` | g/day; explicitly complete finite logs | Same dated-target logic; floor has its own eligible-day count and days at/above floor |
| `execution.steps` | steps/day; selected original writer only | Mean signed distance outside each dated range (zero within range), dates within range, separate prior delta; target min/max are eligible-day means and flagged if changed |
| `execution.lifts`, `execution.aerobic` | unique sessions in selected period; duration separate | Targets and variance use complete configured plan weeks only; baseline frequency remains visible. All-period count delta vs prior is separate |
| `anchorChanges[key]` | load and percent, separately for each exercise/equipment/convention/reps/source key | Maximum finite matched load in each period; percent only when prior load >0; improving >1%, declining <−1%, otherwise stable |
| `recovery.sleep`, `recovery.rhr`, `recovery.hrv` | hours/night, bpm, ms; finite observed means | Current/prior means and counts; latest observation/value; missing dates; stale if latest predates last three completed days |
| `weekend` | kcal/day on complete days, grouped by local Saturday/Sunday vs other days | Each group count; no complete-week claim from partial weeks; no values when group is empty |

Numeric target changes use dates with a known plan and eligible observation only. A missing target effective date yields no historical adherence. Displayed effective target is the eligible-day mean when it changes; the UI says so. A defined week starts on `weekStartsOn` (0 Sunday…6 Saturday). A week counts only when all seven days are inside the reporting period and share a plan version. Unconfigured alignment, partial boundary weeks and midweek plan changes do not fabricate expected attendance; the comparable full-week count is named separately. Missing sessions cannot be distinguished from unlogged ones by this synthetic inventory.

Strength count and direction summaries use per-anchor statuses, so an improving anchor cannot hide a declining one. Unmatched current keys are counted as excluded. `delta.strength` remains a legacy raw-load diagnostic for compatibility; it is neither displayed as an aggregate strength measure nor used to mask a declining anchor. Original writer/record/revision evidence references span both windows. Program movement gaps rely on explicit fixture assignments; lower-body set-target adherence is unconfigured, never inferred from routine names.

A latest weight value is separate from freshness metadata. Absent/stale weight prevents a continue-unchanged trend claim. No configured weight-change rate means no rate-target success/failure label. Waist observations and scale estimates retain date/method/source, without an inferred tissue trend. No comparable endurance performance metric is configured, so the dashboard answers that endurance change is not established while showing attendance and duration.

Next-action priority: a due active decision requires review (with recovery constraint retained); otherwise recovery concern, unknown recent recovery, incomplete food logs, declining anchor, movement gap, incompatible anchors, missing recent weight, then supported restoration of documented execution or continue/review. Restoration requires full eligible target/log coverage and the existing rule's deviation threshold; it never prescribes a new target. Findings are ranked recovery, strength decline, movement gap, plausible execution explanations, other observations. At most three appear inline, alongside material missing evidence. Detailed investigations retain all evidence.

Review dates are optional user choices, never automatic three-week commitments. `reviewState` distinguishes no date, awaiting observations, gathering evidence and a due review with/without sufficient evidence. Sufficiency is deliberately conservative: at least seven post-decision days, complete calorie logs for that interval, a supported weight fit, at least seven sleep and RHR observations with latest readings within the last three completed days, and recorded lifting. It permits reviewing execution/response, not causal attribution. Deferred/rejected decisions are historical choices rather than active adjustments. Every active decision remains visible; history is immutable. Demo decisions are held in the current tab only and reset on reload.

UI rounding: signed rounded zero is displayed as zero; nonfinite/missing values display Unknown. Most daily values are whole units, weight 2 decimals, slopes 2, anchor changes and recovery 1. Calculation precision is unchanged by formatting.


## US presentation boundary

Source observations, target histories, rule thresholds and original decision snapshots remain canonical SI. `usMeasure` and `formatUS` convert only for display. Weight and lifting loads use lb, waist uses in, recorded distance uses mi, elevation uses ft, speed uses mph and pace formats minutes:seconds per mile. Calories remain kcal and protein remains grams, including in the US interface. One pound is exactly 0.45359237 kg; one inch is 2.54 cm; one mile is 1609.344 m; one foot is 0.3048 m. Pace input is seconds/km, converted to seconds/mile before formatting as min/mi. Missing stays unavailable; zero is valid; signed rounded zero does not render as negative zero.

Weight-change evidence now carries structured current/prior SI rate values, so `displayEvidence` renders the same US values as the cards instead of attempting to parse numbers from prose. Charts convert a copy of their source series, including axes and accessible labels. Strength percentages do not change with units. Tests verify every scenario's observations and analytical decisions remain identical after display conversion.

Aerobic distance is summed only when normalized `distanceMeters` observations exist, alongside a count of sessions with distance. Zero distance is a valid observation. Missing distance is not converted to zero or inferred from duration, steps or sport. The present demo fixtures do not include distance; conversion and partial-coverage behavior are tested with separate synthetic cases. Live mapping is not established by this display support.

## Finishing a review

`completeReview` returns a new history, leaves the original action/evidence snapshot unchanged, and appends a review result with the user's outcome/note, review date, then-current selected analysis window, source snapshot and evidence-sufficiency state. The selected action becomes completed and no longer causes a due-review prompt. Continue-plan, conclude and stop outcomes never automatically change targets. Missing evidence remains recorded as insufficient even if the user explicitly chooses to stop or conclude. Completed actions cannot be completed twice. Semantically duplicate active actions are rejected; a new action can be created after closure.

The browser prepares both a proposed plan and proposed decision history before committing either state, so validation failure cannot partially save the action. This remains tab-memory demo behavior: it is not durable storage, synchronization, backup or a private account implementation.
